# Выпуск версий VHR Games SDK

Как выпускать `ru.vhrgames.sdk`, чтобы у разработчиков игр всё обновлялось само и ничего не ломалось.

## Как это устроено

```
коммит в main ──► тег vX.Y.Z ──► GitHub Actions (release.yml): проверка → GitHub Release
                                              │
                    сервер VHR видит новый тег/релиз (GET /games/api/Sdk/versions → latest)
                                              │
        Unity у разработчиков: автопроверка раз в сутки, окно «VHR → Обновление SDK» → «Обновить до X»
```

Сервер берёт `latest` из тегов и релизов этого репозитория, `dependencies` — из `package.json`
тега, `releaseNotes` — из раздела CHANGELOG. Публиковать что-то ещё (на сайт, в реестр) не нужно.

## Порядок выпуска

1. **Поднять версию** (одинаково в двух местах):
   - `package.json` → `"version": "X.Y.Z"`;
   - `Runtime/VhrSdk.cs` → `public const string SdkVersion = "X.Y.Z";`
2. **CHANGELOG.md** — новый раздел сверху: `## [X.Y.Z] - ГГГГ-ММ-ДД` с подразделами «Добавлено»,
   «Изменено», «Исправлено», «Устарело». Этот текст увидят разработчики в Unity и на странице релиза.
3. **README** — если поменялись установка, API или поведение.
4. **Новые файлы и папки внутри пакета** — у каждого свой `.meta` с уникальным GUID (32 hex).
   Папки с `~` на конце (`Documentation~`, `Samples~`, `Installer~`) и скрытые (`.github`) Unity не
   импортирует — им `.meta` не нужны.
5. **Зависимости поменялись** — обновите и `FallbackDependencies` в `Installer~/VhrSdkInstaller.cs`.
   Перед тегом поднимите там `InstallerVersion` и `FallbackLatest` до X.Y.Z. Если меняли ядро
   установщика (регион `VHR-SETUP-CORE`), скопируйте его в `Editor/VhrSetupCore.cs` без изменений.
6. **Проверка локально:**
   ```bash
   node .github/scripts/check-release.mjs --tag vX.Y.Z
   ```
7. **Коммит → тег → push:**
   ```bash
   git commit -am "feat: vX.Y.Z — …"
   git tag vX.Y.Z
   git push origin main vX.Y.Z
   ```
   CI повторит проверку и создаст GitHub Release. Упала проверка — исправьте, удалите тег
   (`git tag -d vX.Y.Z && git push origin :refs/tags/vX.Y.Z`) и поставьте заново.
8. **Установщик изменился** — выложите новый `Installer~/VhrSdkInstaller.cs` на сайт как
   `https://vhrgames.ru/downloads/VhrSdkInstaller.cs`.

Дальше ничего делать не нужно: сервер сам увидит новую версию, а редакторы разработчиков — подскажут обновиться.

> Опубликованный тег **не переписывайте**: Unity кэширует git-пакеты по коммиту, и у части
> разработчиков останется старое содержимое. Нашли ошибку — выпускайте следующий patch.

## SemVer

| Что меняется | Версия | Примеры |
|---|---|---|
| Только исправления, API и поведение для игры прежние | **patch** `1.10.0 → 1.10.1` | баг в релее, текст ошибки, утечка подписки |
| Новое, старое продолжает работать | **minor** `1.10.1 → 1.11.0` | новый сервис, метод, поле в ответе, окно Editor; пометка `[Obsolete]` |
| Ломающие изменения: удалили/переименовали публичный API, сменили сигнатуру или смысл | **major** `1.x → 2.0.0` | удаление устаревших методов, другой формат данных |

Пре-релизы — `X.Y.Z-preview.N`: CI создаёт их как pre-release; ставить их можно только явным тегом.

## Политика устаревания

- Публичный API сначала помечается **`[Obsolete("чем заменить", false)]`** и продолжает работать
  **минимум одну минорную версию** (лучше — до следующей major). Удаление — только в major.
- Устаревшее API добавьте в ответ сервера (`deprecations`: `since`, `api`, `message`) — окно
  «VHR → Обновление SDK» найдёт его в коде игры и покажет, что заменить.
- **Серверные контракты меняются только аддитивно**: новые поля, эндпоинты и коды ошибок; старые поля
  не удаляются и не меняют смысл, пока ими пользуются поддерживаемые версии SDK.
- **Протокол `postMessage` с сайтом (`vhr:*`) — только аддитивно**: новые типы сообщений и
  необязательные поля. Старые сборки игр на платформе работают годами и не пересобираются.
- Ключи `SessionState` `VhrSdk.Update.*` — контракт между версиями SDK (итог обновления сообщает уже
  новая версия): не переименовывать.

## Когда поднимать `minSupported`

`minSupported` — минимальная версия SDK, с которой платформа **принимает новые сборки** (ниже —
`sdk_outdated` при загрузке, а в Unity останавливается WebGL-сборка). Уже опубликованные сборки
продолжают работать.

Поднимать **только** когда старые версии опасны:
- **безопасность** — утечка токена, обход проверки origin, небезопасное хранение;
- **деньги** — покупки, баланс, выплаты (пример: 1.9.0 — покупки только с подтверждением игрока).

Порядок: выпустить исправленную версию → **анонс** разработчикам (сайт, почта, кабинет) со сроком →
после срока поднять `minSupported` на сервере. Ради новых возможностей `minSupported` не поднимаем —
для этого есть `latest` и напоминание об обновлении.
